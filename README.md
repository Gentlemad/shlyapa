# Шляпа

Мобильная игра на угадывание слов. Одна компания, один телефон, три раунда на общем банке слов.

## Что здесь лежит

| Файл | Зачем |
|---|---|
| `src/shlyapa.html` | Исходник прототипа: приложение плюс среда прототипа (рельса состояний, корпус телефона) |
| `build.js` | Вырезает среду прототипа и собирает боевую страницу |
| `index.html` | Результат сборки. Именно его отдаёт GitHub Pages |
| `serve.js` | Локальный сервер для проверки перед публикацией |
| `HANDOFF.md` | Что менялось в последнем заходе и почему: записка для следующей сессии |
| `docs/PRD.md` | Канонические требования: правила, скоуп, экраны, техконтур. Читать первым |
| `docs/CHANGELOG.md` | История версий: что менялось в игре от выпуска к выпуску |
| `worker/` | Ретранслятор отзывов в телеграм и инструкция по его развёртыванию |

Править руками нужно **только `src/shlyapa.html`**. Файл `index.html` пересобирается и коммитится как есть.

## Сборка

```bash
node build.js
```

## Локальная проверка

```bash
node serve.js
```

Открыть http://localhost:4173

Адрес `http://localhost:4173/?fresh` открывает страницу как будто впервые:
чистит ответ про статистику и незаконченную партию. Без этого баннер согласия
показывается один раз на устройство и больше никогда.

## Среда обкатки

```bash
node build.js --dev --out dev.html
```

Собирает страницу с **рельсой состояний**: слева (на узком экране — сверху)
список всех экранов игры, тап по любому переносит прямо туда. Нужна, чтобы
увидеть правку за один тап, а не проходя партию целиком.

В рельсе 18 состояний, включая те, до которых обычным путём идти долго:
баннер cookie показывается один раз на устройство, а вопрос на финале — только
с третьей партии.

Эта сборка **ничего не отправляет**: ни события в базу, ни хиты в Метрику.
Прыжки по экранам — не партии, и в аналитике им не место. За это отвечает
`DEV_BUILD`, который `build.js` подставляет сам.

`dev.html` в репозиторий не коммитится: собирается локально, когда нужна.

## Публикация на GitHub Pages

Первый раз:

1. Создать пустой публичный репозиторий на github.com, например `shlyapa`. Без README, без .gitignore.
2. В папке проекта выполнить:

```bash
git init -b main
git add .
git commit -m "Шляпа: первая версия"
git remote add origin https://github.com/ВАШ_ЛОГИН/shlyapa.git
git push -u origin main
```

3. В репозитории открыть Settings, раздел Pages. В блоке Build and deployment выбрать Source: Deploy from a branch, ветку `main`, папку `/ (root)`. Сохранить.
4. Через минуту адрес будет доступен: `https://ВАШ_ЛОГИН.github.io/shlyapa/`

Дальше каждое обновление:

```bash
node build.js
git add .
git commit -m "что изменилось"
git push
```

## Что нужно знать про хранение

Состояние игры и история последних трёх партий лежат в `localStorage` браузера. Это значит:

- данные привязаны к конкретному браузеру на конкретном устройстве и между устройствами не переносятся;
- очистка данных сайта стирает незаконченную партию и историю;
- для общей истории на несколько устройств понадобится сервер, сейчас его нет.

Для игры это не проблема: партия и так идёт на одном телефоне, который передают по кругу.

## Чего пока нет

- PWA: ни манифеста, ни service worker. Установки на главный экран и офлайна не будет, приложение открывается как обычная страница.
- Иконки приложения и превью для мессенджеров.
- Синхронизации между устройствами.
